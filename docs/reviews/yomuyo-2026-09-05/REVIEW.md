### 実装意図として尊重した判断（指摘対象から外したもの）

- 秘密 URL＋復旧コード方式の認証（ログイン／パスワード／生体認証を持たない）。`02-auth-token.md` で利便性優先と明記済み。

## 1. コード品質

### must-fix

**1-1. 「本棚へ進む」ボタンが何もしない（オンボーディング完了直後に詰まる）**
`src/pages/Onboarding.tsx:29-32`
```tsx
function handleContinue() {
  if (!token) return
  navigate('/', { replace: true })
}
```
すでに `/` にいる状態で同一パスへ `replace` しても `Root`（`src/pages/Root.tsx:5-8`）は再評価されない。`Root` は描画時に `getStoredToken()` を読むだけで、状態として持っていないため。実測: クリック後 1.2 秒経っても「準備ができました」画面のまま（`screenshots/02b-after-continue-click-still-onboarding.png`）。リロードすると本棚が開く。新規ユーザーが最初に押すボタンが無反応、という致命的な導線切れ。
対策: `Root` で `const [token, setToken] = useState(getStoredToken)` を持ち、`Onboarding` に `onReady(token)` を渡して state 更新で切り替える。`TokenEntry` からの遷移は別パスなので現状どおりでよい。

**1-2. 詳細画面から「← 戻る」で一覧に戻れない（さがすタブに落ちる）**
`src/pages/Bookshelf.tsx:20` `useState<Tab>(navState?.tab ?? 'scan')` と `src/pages/BookDetail.tsx:150` `navigate(-1)` の組み合わせ。一覧の `Link` で詳細へ進むと `Bookshelf` がアンマウントされタブ状態が消える。戻ると `Root` が再マウントされ既定の `scan` タブになる。実測で確認済み（一覧→詳細→戻る→「検索／スキャン」画面）。削除後の `navigate('/')`（`BookDetail.tsx:116`）も同様に一覧ではなくスキャンに落ちる。
対策: タブを URL に載せる（`/`, `/list`, `/settings` のネストルート、または `?tab=`）。`history.state` に頼ると `Link` 経由で失われる。

**1-3. `<p>` の中に `<div>` / `<textarea>` を入れている（React が実行時エラーを出す）**
`src/pages/Scan.tsx:479-488`（`<p><label>タグ</label><br /><TagInput .../></p>`）、`Scan.tsx:490-501`（`<p>...<textarea/></p>`）。`console-errors.json` に `In HTML, <div> cannot be a descendant of <p>` が記録されている。ブラウザは `<p>` を自動で閉じるため DOM 構造が意図とずれ、将来のスタイル調整で必ず踏む。`<p>` を `<div>` に置き換えるだけでよい。

**1-4. 保存が 2 段階 API で、後段が失敗すると「保存に失敗」と表示されるが実際は保存済み**
`src/pages/Scan.tsx:190-207`
```tsx
const saved = await callFunction<{ id: string }>('save-book', {...})
if (memoDraft.trim()) {
  await callFunction('update-book', { token, body: { id: saved.id, memo: memoDraft } })
}
```
`update-book` だけが失敗すると `saveState='error'` になり、ユーザーが再度「保存」すると今度は 409 で「すでに保存されています」。メモは失われる。`save-book` に `memo` を受け付けさせて 1 リクエストにするのが最小修正（`supabase/functions/save-book/index.ts:54-64` の `SaveBookRequest` に `memo` を足す）。

**1-5. タグ変更・ステータス変更のエラーが握りつぶされる**
`src/pages/BookDetail.tsx:87-92` `changeTags` に `try/catch` がなく、失敗時は未処理の Promise reject。`changeStatus`（`:75-85`）は `finally` のみで `catch` がなく、`<select>` は元の値に戻るが説明がない。メモ保存（`:94-108`）だけはエラー表示があり、同一画面内で一貫していない。

**1-6. `/b/{token}` が無検証で既存トークンを上書きする**
`src/pages/TokenEntry.tsx:12-16`。URL を 1 文字でも打ち間違えた／古い URL を開いた場合、正しいトークンが無効なもので上書きされ、次回起動時にオンボーディングへ落ちる（本棚が消えたように見える）。復旧コードを控えていないユーザーには実質データ喪失。`get-account` で疎通確認してから保存し、失敗時は既存トークンを残して「この URL は無効です」と表示する。

**1-7. `search-title` / `lookup-google-books` が無認証の公開プロキシになっている**
`supabase/functions/search-title/index.ts:67-127` はトークン検証を行わず、1 リクエストで Google Books API を 3 回叩く（`:98-102`）。一般公開すると誰でも `GOOGLE_BOOKS_API_KEY` のクォータを消費できる。`create-token` と同じ IP レート制限か、トークン必須化のどちらかは公開前に必要。

**1-8. デザイントークンと実装が分断され、ダークモードが壊れている**
`src/index.css:1-51` は CSS 変数と `color-scheme: light dark`＋ダーク用の変数を定義しているが、全ページが `#fff` `#666` `#333` `crimson` などのインライン直書き（例: `Bookshelf.tsx:37-40`, `BookList.tsx:253-256`, `TagInput.tsx:4`）。結果として OS ダーク時は背景だけ暗転し、白背景の「タグ別表示」「新しい順」ボタンは文字が消える（`28-dark-mode-booklist.png`）。短期対処は `color-scheme` とダーク用ブロックを削除してライト固定にすること。中期はトークンに寄せる。

**1-9. `#root` に Vite テンプレートの残骸が残り、全画面が中央揃えになっている**
`src/index.css:53-63`
```css
#root {
  width: 1126px;
  max-width: 100%;
  margin: 0 auto;
  text-align: center;
  border-inline: 1px solid var(--border);
```
`text-align: center` が継承され、ラベル・見出し・リンク・削除ボタンまで全部中央に寄る（2章・4章で詳述）。`width: 1126px` と `border-inline` も本アプリの意図ではない。1 か所直すと配置の問題の半分が解消する。

### nice-to-have

## 4. 配置（レイアウト）

根拠スクショ: `02`, `06`, `08`, `15`, `16`, `21`, `27`, `30`。

### must-fix

- **全要素の中央揃え**（`06`, `15`, `21`: ラベル「ステータス」「タグ」「メモ」が中央、入力欄は左端から、ボタンは中央）。フォームは左揃えが原則で、ラベルと入力欄の左端が揃わないと視線が往復する。原因は `index.css:57` の `text-align: center`（1-9）。

- **カメラ拒否パネルが横にはみ出す**（`08`: 右端が画面外）。`Scan.tsx:347-360` で `width: 100%` に `padding: 1rem` を足しており `box-sizing: border-box` が無い。実測 `scrollWidth 405 > innerWidth 390` で横スクロールが発生する。
- **ボトムナビとコンテンツの重なり**（`10`, `30`: 3 列グリッドの最終行にナビが重なる）。`paddingBottom: 5rem`（80px）に対しナビは高さ約 56px＋下 16px＋影で、最終行の表紙が半分隠れる。`env(safe-area-inset-bottom)` も考慮されていない（iPhone のホームバー領域に食い込む）。`calc(72px + env(safe-area-inset-bottom) + 1rem)` に。
- **デスクトップでグリッドが 3 列固定**（`27`: 1 枚の表紙が 350px 幅）。`gridTemplateColumns: 'repeat(3, 1fr)'`（`BookList.tsx:57`）。`repeat(auto-fill, minmax(110px, 1fr))` にすれば端末幅に応じて 3〜9 列になる。またナビが `left:16 / right:16` でコンテナ幅 1126px を無視して画面全幅に伸びる（`Bookshelf.tsx:33-35`）。

### nice-to-have

- 一覧のコントロール群が 4 段（検索欄／ステータスチップ／表示・並び順／タグ）＋`details` で、初回表示で表紙が出るまでに約 640px スクロールする（`10`）。320px 幅では 5 段（`30`）。並び順・表示切替はアイコンボタン 1 つに畳み、タグ列を検索欄の下に寄せると 2 段に収まる。
- 詳細画面の「削除」が青空文庫リンクの直後に密着している（`16`）。破壊操作は最下部に区切り線と余白を置いて隔離する。
- 詳細の表紙は `maxWidth: 160`（`BookDetail.tsx:158`）で固定。横向き表紙（`No.7` のようなケース）は高さが不揃いになる。`aspect-ratio: 2/3` の枠に `object-fit: contain` で収める。
- オンボーディングの URL ブロック（`02`）は 32 文字トークンが 2 行に折り返し、`wordBreak: break-all` で任意位置で切れる。URL は「コピー」ボタンで扱う前提にして 1 行に省略表示（末尾 …）でもよい。

## 5. アクセシビリティ

根拠: `axe-results.json`（axe-core 4.10）、Playwright での実測、コード。

### must-fix

- **キーボードフォーカスが見えない入力欄**: `TagInput.tsx:126` `outline: 'none'`。実測 `outlineStyle: none`。タグ入力欄に Tab で入っても位置が分からない。`:focus-visible` で親枡に枠を出す。
- **色だけで伝えるステータス**: 一覧の右上ドット（`BookList.tsx:93-105`）は `title` 属性のみ。タッチ端末では `title` は表示されず、スクリーンリーダーにも読まれない（`span` に role/aria-label 無し）。`aria-label` を付けるか、可視テキストを併記する。
- **コントラスト不足（axe: serious）**: 表紙無し本のタイトル `#999` on `#eee`（2.3:1、`10`, `11`）、青空文庫「うまく開けない場合は」`#888` 12px（`16`, `18`）、削除ボタン `crimson` on 既定グレー。WCAG AA の 4.5:1 を満たすよう `#666` 以上に。
- **タブ UI に role が無い**: 検索／スキャンのセグメント（`Scan.tsx:245-263`）とボトムナビ（`Bookshelf.tsx:43-63`）はいずれも `button` に太字を付けているだけ。選択状態が支援技術に伝わらない。`aria-pressed` か `role="tablist"/"tab"` + `aria-selected` を付ける。`nav` に `aria-label="メインナビゲーション"` も。
- **ラベル未関連付け**: `Scan.tsx:480` `<label>タグ</label>`、`BookDetail.tsx:188` 同様（`htmlFor` 無し）。タグ入力欄は `placeholder` だけが名前になっている。復元画面の入力欄（`Recover.tsx:37-52`）も `label` が無く、エラー文（`:57`）が `aria-describedby` で結びついていない。

### nice-to-have

- **状態変化の通知**: 「保存しました」「保存に失敗しました」「検索中…」などは静的な `<p>` で、`role="status"` / `aria-live` が無い。
- **タップ領域**: タグの「×」削除ボタン（`TagInput.tsx:92-106`）は `padding: 0`・`lineHeight: 1` で約 14px 角。最低 24px（推奨 44px）を確保する。
- **`window.confirm` による削除確認**（`BookDetail.tsx:112`）はアクセシブルだが、PWA スタンドアロン表示では OS ダイアログが浮いて没入感を壊す。アプリ内ダイアログにするなら `<dialog>` でフォーカス管理を維持する。
- **画像の代替テキスト**: 一覧の表紙 `alt={book.title}`（`BookList.tsx:67`）は良い。詳細・候補の `alt=""` も隣にタイトルがあるので妥当。
- **`prefers-reduced-motion`**: 現状アニメーションが無いので問題は無いが、今後ローディングやトーストを足す際に考慮する。
- **フォントサイズ**: ルート 16px（モバイル）、補助テキスト 12px（`0.75rem`）。12px は日本語では読みづらい。最小 13〜14px に。

## 6. 追加した方が良い要素

### must-fix（公開前に必要）

- **ISBN が読めても書誌が無い本の手入力登録**（2 章）。タイトルだけで保存できれば、店頭での「とりあえず記録」という主目的を落とさない。
- **カメラ設定への案内文とタイトル検索への逃げ道**（2 章）。
- **PWA アイコンと `theme-color`**（1 章）。ホーム画面追加を勧める以上は必須。
- **プライバシーポリシー／利用規約と外部 API のクレジット表記**。openBD・国立国会図書館サーチ・Google Books・青空文庫・BinB のデータを表示しており、Google Books API は利用規約で帰属表示を求めている。設定画面下部に「このアプリについて」を置く。
- **オフライン時の表示**。`vite-plugin-pwa` の `generateSW` で precache は出るが、Edge Function 失敗時の画面は「読み込みに失敗しました」（`BookList.tsx:356`）のみで再試行ボタンも無い。書店の地下など電波の弱い場所が主戦場なので、「再読み込み」ボタンと最後に取得した一覧のキャッシュ表示は要る。

### nice-to-have

- **秘密 URL の QR 表示**（`06-open-questions.md` にスコープ外として記載済み）。設定画面に QR を出すと別端末への引き継ぎが「メールで送る」より速い。
- **書店リンクの「外部サイト」アイコン**と、Amazon アフィリエイトを使う場合の明示（設定 or About）。
- **一覧の並び順にタイトル順・著者順**。現状は登録日の昇降のみ（`BookList.tsx:10`）。冊数が増えると探せない。
- **図書館在庫（カーリル）**は `03-screens.md` の主要機能だが未着手。「店頭で見つけて図書館で借りる」という物語の後半が無いので、ロードマップ上の位置を再確認する価値がある。
- **本棚の書き出し（CSV / JSON）**。秘密 URL 方式はアカウント喪失のリスクを利用者が負う設計なので、手元にデータを持ち出せる手段が信頼につながる。
- **検索候補の「すでに登録済み」表示**。同じ本を選んでから 409 で知るより、候補一覧の時点でチェックマークを出す。
- **一覧からのステータス変更**（長押し／スワイプ）。現状は詳細に入って `select` を操作する必要があり、読了を付けるだけの操作に 3 タップかかる。

## 7. 総評

機能の骨格（ISBN スキャン→書誌補完→保存→一覧→詳細→書店／青空文庫）はそろっていて、Edge Function 経由のデータ設計や青空文庫のマッチングなど裏側は丁寧。一方で表側は、Vite テンプレートの `#root` スタイルとブラウザ既定のフォーム部品のまま画面を積み上げた状態で、一般ユーザー向けプロダクトの水準には届いていない。さらに新規ユーザーが最初に触る 2 つの導線（「本棚へ進む」、詳細→戻る）が壊れている。

**次に着手すべきフェーズは「導線バグの修正（1-1〜1-3）→ `index.css` の残骸除去とボタン／フォームの共通スタイル定義」。** 新機能より先に、この 2 つを 1 コミットずつで終わらせると、既存のスクショと `tools/shoot.cjs` でそのまま前後比較ができる。
